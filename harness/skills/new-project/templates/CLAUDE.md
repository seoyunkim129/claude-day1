## 기록 규칙 (가장 중요)

작업이 한 단계 끝날 때마다, 시키지 않아도 아래 두 파일을 채운다. 형식은 `/collab-harness:record` 스킬을 따른다.

| 파일 | 적는 것 | 적지 않는 것 |
| --- | --- | --- |
| `docs/작업기록.md` | **무엇을 만들었나** — 날짜, 한 일, 숫자, 실패, 검증 결과, 남은 한계 | 감상, 다짐 |
| `docs/포트폴리오-기록.md` | **누가 왜 그렇게 정했나** — 내 결정(D), 검증(V), AI가 틀린 것(M), 잘 통한 프롬프트 원문(P) | 정리된 결론만 |
| `docs/세션로그.md` | 훅이 자동으로 쓴다. 손대지 않는다 | — |

- **AI가 틀렸던 기록(M)은 절대 지우지 않는다.** "검증하며 일했다"는 증거는 성공이 아니라 그 표다.
- 기록의 주어는 **나**다. (X: "AI가 분류 기준을 설계했다" → O: "내가 분류를 3개로 정하고 AI에게 구현시켰다")
- 날짜는 "어제", "지난주" 대신 실제 날짜로 적는다.
- 내가 AI 말을 바로잡거나 되물은 순간이 있으면, 그 단계가 끝날 때 M 또는 V로 남긴다.

## 일하는 방식

1. **긴 작업은 시작 전에 계획을 말하고 승인을 받는다.** 바로 코드부터 쓰지 않는다.
2. **설명은 쉬운 말로.** 전문 용어를 쓰면 바로 옆에 쉬운 말을 붙이고, 처음 나온 용어는 포트폴리오-기록의 용어 사전에 추가한다.
3. **추측으로 보고하지 않는다.** "고쳤습니다"는 직접 재보고 숫자가 나왔을 때만 쓴다. 못 재봤으면 "아직 확인 못 했습니다"라고 쓴다.
4. **확인 수준을 밝힌다.** 문서·논문·데이터를 근거로 쓸 때 본문 확인 / 일부만 / 기억에 의존 을 구분한다.
5. **되돌리기 어려운 일(삭제, 배포, 외부 전송)은 먼저 물어본다.**
6. 내가 지적한 내용이 맞으면 변명 없이 고치고, AI 판단이 맞다고 생각하면 근거를 대고 반박한다.

## 절대 하지 말 것

- 비밀키·토큰·비밀번호의 **실제 값**을 화면, 로그, 문서, 답변, 커밋에 출력하지 않는다. 있다/없다만 확인한다.
- `.env` 같은 비밀 파일을 git에 올리지 않는다.
- robots.txt가 막아둔 사이트를 크롤링하지 않는다. 공식 API를 쓴다.
- 출처를 모르는 값을 "확인됨"으로 표시하지 않는다. 모르면 **모른다고 표시**한다.

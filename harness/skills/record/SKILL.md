# 단계 기록

기록의 목적은 나중에 면접에서 "AI를 쓰면서도 판단은 본인이 했다"를 **증거로** 보여주는 것이다. 정리된 결론보다 되물은 순간, 틀린 걸 잡은 순간이 더 중요하다.

## 1. 이번 단계에서 무엇이 있었는지 대화를 다시 훑는다

다음을 빠짐없이 찾는다.

- 사용자가 **고른 것** (선택지가 있었고 사용자가 정함) → D
- 사용자가 AI 말을 **의심하거나 확인을 시킨 것** ("맞아?", "출처는?", "직접 열어봤어?") → V
- AI(나)가 **틀렸던 것** — 사용자가 잡았든, 실행 결과나 시험으로 드러났든 → M. 내가 틀린 건 축소하지 않는다
- 결과가 좋았던 사용자 프롬프트 → P (원문 그대로, 오타 포함)
- AI가 정한 숫자와 사용자가 정한 숫자 → 5절 표
- 처음 나온 전문 용어 → 6절 용어 사전

## 2. 형식

번호는 파일에 이미 있는 마지막 번호 다음부터 잇는다.

**작업기록.md** (맨 아래에 덧붙임, 기존 내용은 고치지 않음)
```
## YYYY-MM-DD — 한 줄 제목

- **하려던 것**:
- **한 것**:
- **숫자**: (직접 잰 값만. 못 쟀으면 "아직 못 잼")
- **검증**:
- **막힌 것 / 남은 한계**:
```

**포트폴리오-기록.md**

D (1절)
```
### D{n} · 무엇을 정했는지 한 문장

- **언제**: YYYY-MM-DD
- **상황**:
- **고를 수 있었던 것**:
- **내가 고른 것과 이유**:
- **바뀐 결과**:
```

V (2절)
```
### V{n} · 무엇을 의심했는지 한 문장

- **AI가 한 말**: (가능하면 인용)
- **내가 의심한 이유**:
- **어떻게 확인했나**:
- **결과**: (M과 연결되면 M 번호)
```

M (3절 표에 한 줄)
```
| M{n} | YYYY-MM-DD | AI가 틀린 내용 | 어떻게 드러났나 | 누가 먼저 발견했나 (나 / AI(시험으로 발견) / AI(내가 시킨 확인 과정에서)) | 어떻게 고쳤나 |
```

P (4절) — 제목 한 줄 + 코드블록에 원문 + 왜 잘 통했는지 한 줄.

## 3. 규칙

- 주어는 사용자다. "AI가 설계했다" 대신 "내가 ~로 정하고 AI에게 구현시켰다". 단, 사용자가 실제로 정하지 않은 걸 정한 것처럼 쓰지 않는다. AI 제안을 받아들였으면 "AI 제안 → 내가 채택"으로 쓴다.
- M은 **절대 지우거나 고쳐 쓰지 않는다.** 정정이 필요하면 새 줄로 덧붙인다.
- 날짜는 실제 날짜. 숫자는 출처가 있는 것만.
- 쓰기 전에 무엇을 몇 개 추가할지 (예: "D 1개, V 2개, M 1개") 짧게 말하고 바로 쓴다. 끝나면 추가한 번호를 알려준다.
- 기록할 게 없으면 억지로 만들지 않고 "이번 단계엔 새 결정·검증이 없었다"고 말한다.
